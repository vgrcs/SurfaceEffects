\section{Operational Semantics}
\label{sec:opsem}

The operational semantics has one primitive execution relation: the
continuation-machine step $s\longrightarrow s'\,;\,\eta$.  The other judgments
below are derived or auxiliary relations built around that step.  They are
kept distinct because they play different roles in the metatheory.

\begin{center}
\small
\begin{tabular}{@{}>{\raggedright\arraybackslash}p{.18\linewidth}
                  >{\raggedright\arraybackslash}p{.33\linewidth}
                  >{\raggedright\arraybackslash}p{.39\linewidth}@{}}
\toprule
\textbf{Layer} & \textbf{Judgment} & \textbf{Role}\\
\midrule
machine step
  & $s\longrightarrow s'\,;\,\eta$
  & one continuation-machine step emitting one trace fragment\\
finite execution
  & $s\longrightarrow^{*}s'\,;\,\phi$
  & accumulated machine trace, represented as a list of actions\\
trace view
  & $\mathsf{view}(s,\Phi,s')$
  & structured view whose flattening is a machine trace\\
scheduled pair run
  & $s\Longrightarrow_{\mathsf{sch}}^{\Phi_L,\Phi_R}s'$
  & finite run-phase scheduler built from branch machine steps\\
\bottomrule
\end{tabular}
\end{center}

The notation is intentionally separated.  Machine execution \emph{produces}
trace fragments; the finite-run relation concatenates them into a list trace.
The structured trace view used by the structured terminal theorem is derived
from machine steps and flattens back to the same list trace.  A one-step
transition emits only a fragment $\eta$: administrative steps emit $\Nil$, while
heap operations emit singleton fragments such as $\Alloc(l\at r)$,
$\Read(l\at r)$, and $\Write(l\at r)$.  The trace of a longer execution is not
stored in the ordinary state or continuation; the pair-parallel runtime state
temporarily stores the two branch traces so it can perform the final checked
trace-disjointness test.

\begin{formalbox}{Machine Operations}
\small
\[
\begin{array}{rcll}
\mathsf{init}(H,E,P,e)\in\mathit{State}
  & \triangleq & \langle H,E,P,e,\mathsf{doneK}\rangle
  & \text{initial expression state}\\
\mathsf{pairRun}(s_1,s_2,\phi_1,\phi_2,k)\in\mathit{State}
  & \triangleq & \text{run }s_1,s_2\text{ with traces }\phi_1,\phi_2
  & \text{pair-parallel run state}\\
\mathsf{heap}(s)\in\mathit{Heap}
  & \triangleq & \text{the }H\text{ carried by }s
  & \text{state heap projection}\\
s[H]\in\mathit{State}
  & \triangleq & \text{state }s\text{ with heap }H
  & \text{heap replacement}
\end{array}
\]

For a list trace $\phi$, write
\[
\mathsf{Wr}(\phi)=
  \{\,l\at r \mid \Write(l\at r)\in\phi\,\}
\]
for its heap-write footprint.  If $W$ is a set of heap addresses, write
$H_1\equiv_{\overline W}H_2$ when the two heaps agree outside $W$:
\[
H_1\equiv_{\overline W}H_2
\quad\Longleftrightarrow\quad
\forall a.\; a\notin W \Rightarrow H_1(a)=H_2(a).
\]
\end{formalbox}

\begin{formalbox}{Finite Machine Executions}
\small
\noindent\textbf{Finite execution}\hfill $\boxed{s\longrightarrow^{*}s'\,;\,\phi}$

\rulepair{
\inferrule*[lab={[TR-Refl]}]{ }
  {s\longrightarrow^{*}s\,;\,\Nil}
}{
\inferrule*[lab={[TR-Step]}]
  {s\longrightarrow s_1\,;\,\eta \\
   s_1\longrightarrow^{*}s_2\,;\,\phi}
  {s\longrightarrow^{*}s_2\,;\,\eta\tracecat\phi}
}
\end{formalbox}

Each finite execution accumulates one-step fragments by induction; $\tracecat$
denotes list concatenation for machine traces and $\Nil$ is the empty trace.
We write $\phi\equiv_{\mathsf{perm}}\phi'$ when two list traces contain the same
actions up to permutation.
Ordinary expression evaluation is the special case
$\mathsf{init}(H,E,P,e)\longrightarrow^{*}\mathsf{done}(H',v)\,;\,\phi$.
A surface-effect term is just an ordinary expression of type $\mathsf{eff}$;
there is no separate surface-effect evaluator.

The scheduled pair-run relation introduced below is finite in the same
inductive sense, but it is not another reflexive-transitive closure of the
ordinary global step relation. Each nonfinal scheduled rule consumes one
ordinary machine step from one branch and then recurses; the global scheduled
order may differ from the ordinary left-to-right machine order.

The continuation machine accumulates list traces. A trace view is either a
one-step fragment $\eta$ or a sequential/parallel composition of views. The
structured terminal correctness theorem uses this auxiliary view together with
a flattening map back to the underlying machine trace. The first two rules
are the two cases of the fragment form $\eta$.

\begin{formalbox}{Trace Views}
\small
\noindent\textbf{Trace-view flattening}\hfill
  $\boxed{\mathsf{flatten}(\Phi)=\phi}$

\rulepair{
\inferrule*[lab={[V-Nil]}]{ }
  {\mathsf{flatten}(\Nil)=[\,]}
}{
\inferrule*[lab={[V-Action]}]{ }
  {\mathsf{flatten}(\iota)=[\iota]}
}

\rulepair{
\inferrule*[lab={[V-Seq]}]
  {\mathsf{flatten}(\Phi_1)=\phi_1 \\
   \mathsf{flatten}(\Phi_2)=\phi_2}
  {\mathsf{flatten}(\Phi_1\tracecat\Phi_2)=\phi_1\tracecat\phi_2}
}{
\inferrule*[lab={[V-Par]}]
  {\mathsf{flatten}(\Phi_1)=\phi_1 \\
   \mathsf{flatten}(\Phi_2)=\phi_2}
  {\mathsf{flatten}(\Phi_1\parallel\Phi_2)=\phi_1\tracecat\phi_2}
}
\end{formalbox}

The flattening map records only the emitted list trace: both sequential and
parallel view composition flatten by concatenating the component traces.

\begin{formalbox}{Trace-View Executions}
\small
\noindent\textbf{Structured finite execution}\hfill
  $\boxed{\mathsf{view}(s,\Phi,s')}$

\begin{rulemathpar}
\inferrule*[lab={[View-Refl]}]{ }
  {\mathsf{view}(s,\Nil,s)}
\end{rulemathpar}

\rulepair{
\inferrule*[lab={[View-Step]}]
  {s\longrightarrow s'\,;\,\eta}
  {\mathsf{view}(s,\eta,s')}
}{
\inferrule*[lab={[View-Seq]}]
  {\mathsf{view}(s_1,\Phi_1,s_2) \\
   \mathsf{view}(s_2,\Phi_2,s_3)}
  {\mathsf{view}(s_1,\Phi_1\tracecat\Phi_2,s_3)}
}
\end{formalbox}

Trace-view execution is a structured presentation of finite machine execution:
if $\mathsf{view}(s,\Phi,s')$, then
$s\longrightarrow^{*}s'\,;\,\mathsf{flatten}(\Phi)$; conversely, every finite
machine execution has a trace view with the same flattened trace.

The initial state for expression $e$ is $\mathsf{init}(H,E,P,e)$; terminal
states $\mathsf{done}(H,v)$ and $\mathsf{error}(H)$ have no outgoing machine
step.  The error state is the checked-failure terminal used when a
pair-parallel computed-effect or trace check fails.  Continuations are
bookkeeping devices for the call-by-value evaluation order.
A frame records the expression still to be evaluated, the environment and region
map needed to resume evaluation, and the continuation to resume afterward.
Application frames first remember the unevaluated argument while the function
position is evaluated, then remember the closure while the argument is
evaluated, and finally enter either the computational body or the surface-effect body
with the recursive name and argument bound.  Heap-operation frames remember the
pending operation and the region environment while a location or value
subexpression is evaluated.  The trace emitted while evaluating functions,
arguments, or surface-effect terms is the machine trace of that evaluation.  A computed
effect is the value returned by evaluating the corresponding surface-effect expression.

\begin{formalbox}{Small-Step Operational Semantics}
\small
\noindent\textbf{One machine step}\hfill $\boxed{s\longrightarrow s'\,;\,\eta}$
\ruletriple{
\inferrule*[lab={[S-Const]}]{ }

   \langle H,n,k\rangle\,;\,\Nil}

\inferrule*[lab={[S-Var]}]{E(x)=v}
  {\langle H,E,P,x,k\rangle
   \longrightarrow
   \langle H,v,k\rangle\,;\,\Nil}

   \longrightarrow

\begin{rulemathpar}
\inferrule*[lab={[S-Clos]}]

\end{rulemathpar}

\begin{rulemathpar}

   \langle H,E,P,e_a,K^e_a(E',P',f,x,e_b,e_s,k)\rangle\,;\,\Nil}
\end{rulemathpar}

\inferrule*[lab={[S-Eapp-Body]}]
  {E''=E'[f\mapsto v_f][x\mapsto v_a] \\
   v_f=\langle E',P',\mu f.\lambda x.\{e_b\mid e_s\}\rangle}
  {\langle H,v_a,K^e_a(E',P',f,x,e_b,e_s,k)\rangle
   \longrightarrow
   \langle H,E'',P',e_s,k\rangle\,;\,\Nil}
\end{rulemathpar}

\begin{rulemathpar}
\inferrule*[lab={[S-Alloc]}]
  {P(p)=r \qquad \mathsf{fresh}(H,r)=l}
  {\langle H,v,K^{ref}(p,P,k)\rangle

\end{rulemathpar}

\begin{rulemathpar}
\inferrule*[lab={[S-Get]}]
  {P(p)=r \qquad H(r,l)=v}
  {\langle H,l\at r,K^{get}(p,P,k)\rangle
   \longrightarrow
   \langle H,v,k\rangle\,;\,\Read(l\at r)}
\end{rulemathpar}

\begin{rulemathpar}
\inferrule*[lab={[S-Set]}]
  {P(p)=r \qquad H(r,l)\neq\bot}
  {\langle H,v,K^{set}(p,l,P,k)\rangle
   \longrightarrow
   \langle H[(r,l)\mapsto v],(),k\rangle\,;\,\Write(l\at r)}
\end{rulemathpar}
\end{formalbox}

\paragraph{Effect-valued expression steps.}
Surface-effect terms are ordinary expressions whose values are computed effects.
Abstract surface-effect forms return region-level actions without touching the heap;
concrete surface-effect forms first evaluate their argument and then return a concrete
computed action. These rules are ordinary machine steps and therefore emit
$\Nil$.

\ruletriple{

   \langle H,\Rs(r),k\rangle\,;\,\Nil}
}{
\inferrule*[lab={[S-Abst-Write]}]{P(p)=r}

}{
\inferrule*[lab={[S-Abst-Alloc]}]{P(p)=r}

\begin{formalbox}{Checked Pair-Parallel Steps}
\small
\noindent\textbf{One machine step}\hfill $\boxed{s\longrightarrow s'\,;\,\eta}$

The checked pair-parallel form is operationally specialized to two computational
applications.  The corresponding surface-effect applications are evaluated
first.  If the computed-effect precheck fails, execution reaches the terminal
checked-failure state $\mathsf{error}(H)$; if it succeeds, the machine runs the
left branch to completion, then the right branch, accumulating separate branch
traces and checking them before returning the pair.  This left-then-right order
is the ordinary machine semantics.  For the scheduler theorem below, the same
run states are also equipped with a derived scheduled relation: it does not add
a new source step, but allows either live branch to take the next run-phase step
while recording the two branch trace views separately.
For compactness, write
\[
\begin{array}{rcl}
\vec e & \triangleq & (e_{f1},e_{a1},e_{f2},e_{a2})\\
e_i^\mu & \triangleq & \capp e_{fi}\,e_{ai}\\
e_i^e & \triangleq & \eapp e_{fi}\,e_{ai}.
\end{array}
\]
\begin{rulemathpar}
\inferrule*[lab={[S-Pair-Start]}]{ }
  {\langle H,E,P,\pairpar{e_1^\mu}{e_2^\mu},k\rangle
   \longrightarrow
   \langle H,E,P,e_1^e,K^{\parallel}_1(\vec e,E,P,k)\rangle\,;\,\Nil}
\end{rulemathpar}

\begin{rulemathpar}
\inferrule*[lab={[S-Pair-Eff1]}]{ }
  {\langle H,\mathsf{eff}(\Theta_1),
      K^{\parallel}_1(\vec e,E,P,k)\rangle
   \longrightarrow
   \langle H,E,P,e_2^e,K^{\parallel}_2(\vec e,E,P,\Theta_1,k)\rangle\,;\,\Nil}
\end{rulemathpar}

\begin{rulemathpar}
\inferrule*[lab={[S-Pair-Check-OK]}]
  {\neg(\Theta_1 \effconflict \Theta_2)}
  {\langle H,\mathsf{eff}(\Theta_2),
      K^{\parallel}_2(\vec e,E,P,\Theta_1,k)\rangle
   \longrightarrow
   \mathsf{pairRun}(
      \mathsf{init}(H,E,P,e_1^\mu),
      \mathsf{init}(H,E,P,e_2^\mu),
      [\,],[\,],k)\,;\,\Nil}
\end{rulemathpar}

\begin{rulemathpar}
\inferrule*[lab={[S-Pair-Check-Fail]}]
  {\Theta_1 \effconflict \Theta_2}
  {\langle H,\mathsf{eff}(\Theta_2),
      K^{\parallel}_2(\vec e,E,P,\Theta_1,k)\rangle
   \longrightarrow
   \mathsf{error}(H)\,;\,\Nil}
\end{rulemathpar}

\begin{rulemathpar}
\inferrule*[lab={[S-Pair-Run-L]}]
  {s_1\longrightarrow s'_1\,;\,\eta}
  {\mathsf{pairRun}(s_1,s_2,\phi_1,\phi_2,k)
   \longrightarrow
   \mathsf{pairRun}(s'_1,
      s_2[\mathsf{heap}(s'_1)],
      \phi_1\tracecat\eta,\phi_2,k)\,;\,\eta}
\end{rulemathpar}

\begin{rulemathpar}
\inferrule*[lab={[S-Pair-Run-R]}]
  {s_2\longrightarrow s'_2\,;\,\eta}
  {\mathsf{pairRun}(\mathsf{done}(H_1,v_1),s_2,\phi_1,\phi_2,k)
   \longrightarrow
   \mathsf{pairRun}(\mathsf{done}(\mathsf{heap}(s'_2),v_1),
      s'_2,\phi_1,\phi_2\tracecat\eta,k)\,;\,\eta}
\end{rulemathpar}

\begin{rulemathpar}
\inferrule*[lab={[S-Pair-Done-OK]}]
  {\neg(\phi_1 \traceconflict \phi_2)}
  {\mathsf{pairRun}(\mathsf{done}(H,v_1),\mathsf{done}(H,v_2),\phi_1,\phi_2,k)
   \longrightarrow
   \langle H,(v_1,v_2),k\rangle\,;\,\Nil}
\end{rulemathpar}

\begin{rulemathpar}
\inferrule*[lab={[S-Pair-Done-Fail]}]
  {\phi_1 \traceconflict \phi_2}
  {\mathsf{pairRun}(\mathsf{done}(H,v_1),\mathsf{done}(H,v_2),\phi_1,\phi_2,k)
   \longrightarrow
   \mathsf{error}(H)\,;\,\Nil}
\end{rulemathpar}
If either branch reaches $\mathsf{error}(H)$, the pair-parallel state steps to
the same checked-failure terminal state.
\end{formalbox}

\begin{formalbox}{Scheduled Pair-Parallel Runs}
\small
\noindent\textbf{Scheduled run}\hfill
  $\boxed{s\Longrightarrow_{\mathsf{sch}}^{\Phi_L,\Phi_R}s'}$

Write $s\notin\mathsf{Err}$ when $s\neq\mathsf{error}(H)$ for every heap $H$.
The final cases coincide with the checked pair-parallel run phase.
For example, [Sch-Done-OK] has the same state-level premise and conclusion as
[S-Pair-Done-OK], but it is a base case of the finite scheduled relation rather
than one primitive machine step. Its branch views are $\Nil,\Nil$ because the
join itself emits no branch action; the accumulated branch traces
$\phi_1,\phi_2$ are already stored in the $\mathsf{pairRun}$ state.

\rulepair{
\inferrule*[lab={[Sch-Err-L]}]{ }
  {\mathsf{pairRun}(\mathsf{error}(H),s_2,\phi_1,\phi_2,k)
   \Longrightarrow_{\mathsf{sch}}^{\Nil,\Nil}
   \mathsf{error}(H)}
}{
\inferrule*[lab={[Sch-Err-R]}]{ }
  {\mathsf{pairRun}(s_1,\mathsf{error}(H),\phi_1,\phi_2,k)
   \Longrightarrow_{\mathsf{sch}}^{\Nil,\Nil}
   \mathsf{error}(H)}
}

\rulepair{
\inferrule*[lab={[Sch-Done-OK]}]
  {\neg(\phi_1 \traceconflict \phi_2)}
  {\mathsf{pairRun}(\mathsf{done}(H,v_1),\mathsf{done}(H,v_2),\phi_1,\phi_2,k)
   \Longrightarrow_{\mathsf{sch}}^{\Nil,\Nil}
   \langle H,(v_1,v_2),k\rangle}
}{
\inferrule*[lab={[Sch-Done-Fail]}]
  {\phi_1 \traceconflict \phi_2}
  {\mathsf{pairRun}(\mathsf{done}(H,v_1),\mathsf{done}(H,v_2),\phi_1,\phi_2,k)
   \Longrightarrow_{\mathsf{sch}}^{\Nil,\Nil}
   \mathsf{error}(H)}
}

\begin{rulemathpar}
\inferrule*[lab={[Sch-Run-L]}]
  {s_1\longrightarrow s'_1\,;\,\eta \\
   s_2\notin\mathsf{Err} \\
   \mathsf{pairRun}(s'_1,s_2[\mathsf{heap}(s'_1)],
      \phi_1\tracecat\eta,\phi_2,k)
      \Longrightarrow_{\mathsf{sch}}^{\Phi_L,\Phi_R} s}
  {\mathsf{pairRun}(s_1,s_2,\phi_1,\phi_2,k)
      \Longrightarrow_{\mathsf{sch}}^{\eta\tracecat\Phi_L,\Phi_R} s}
\end{rulemathpar}

\begin{rulemathpar}
\inferrule*[lab={[Sch-Run-R]}]
  {s_2\longrightarrow s'_2\,;\,\eta \\
   s_1\notin\mathsf{Err} \\
   \mathsf{pairRun}(s_1[\mathsf{heap}(s'_2)],s'_2,
      \phi_1,\phi_2\tracecat\eta,k)
      \Longrightarrow_{\mathsf{sch}}^{\Phi_L,\Phi_R} s}
  {\mathsf{pairRun}(s_1,s_2,\phi_1,\phi_2,k)
      \Longrightarrow_{\mathsf{sch}}^{\Phi_L,\eta\tracecat\Phi_R} s}
\end{rulemathpar}
\end{formalbox}

Thus a left-branch step is the same state update as [S-Pair-Run-L]. A
right-branch step may occur before the left branch has finished; after such a
step the left state is rebased to the right branch's new heap. The side
conditions prevent either branch from continuing to schedule steps after the
other branch has already reached $\mathsf{error}(H)$. From empty branch
accumulators, the final stored branch traces are exactly
$\mathsf{flatten}(\Phi_L)$ and $\mathsf{flatten}(\Phi_R)$. The normalized
scheduler trace view is $\Phi_L\parallel\Phi_R$, whose flattening is the
canonical branch projection
$\mathsf{flatten}(\Phi_L)\tracecat\mathsf{flatten}(\Phi_R)$ even when the
scheduled execution interleaves the one-step fragments.

The connection back to finite machine executions is an embedding, not an
identification. Let
\[
s_0 =
\mathsf{pairRun}(
  \mathsf{init}(H,E,P,e_L^\mu),
  \mathsf{init}(H,E,P,e_R^\mu),
  [\,],[\,],\mathsf{doneK}).
\]
If the ordinary left-to-right machine run terminates,
\[
s_0\longrightarrow^{*}\mathsf{done}(H',v)\,;\,\phi,
\]
then there exist branch views $\Phi_L,\Phi_R$ such that
\[
s_0\Longrightarrow_{\mathsf{sch}}^{\Phi_L,\Phi_R}
  \langle H',v,\mathsf{doneK}\rangle
\qquad\text{and}\qquad
\phi\equiv_{\mathsf{perm}}
\mathsf{flatten}(\Phi_L\parallel\Phi_R).
\]
The converse is intentionally not stated as an ordinary finite execution:
arbitrary scheduled runs may take a right-branch step before the ordinary
machine would do so.

Surface-effect evaluation is proved heap-neutral from typing: if a well-typed
surface-effect execution emits a heap-neutral trace, the final heap is the
